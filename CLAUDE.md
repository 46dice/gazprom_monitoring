# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Тестовое задание: веб-приложение с линейными графиками (Recharts) по Excel-файлу
`backend/data/База данных_СДОиС.xlsx` — реестр тройников на КС (~30 тыс. строк, 48 столбцов).
Пользователи правят **только Excel**; бэкенд его читает и отдаёт, фронт строит графики и
обновляется сам, когда файл изменился. Графиков произвольное число, оси настраиваются
перетаскиванием полей.

| Папка | Что это |
|---|---|
| `backend/` | FastAPI, только чтение Excel — рабочий код |
| `frontend/` | React + TS + zustand + Recharts; на момент создания этого файла — только структура из пустых файлов |
| `fastapi-onion-architecture/` | **учебный образец** архитектуры бэкенда, не часть приложения; не править |

Образец архитектуры фронтенда — проект Кленова в `C:\proj\Кленов` (вне репозитория).

## Скиллы

Перед работой загружай соответствующий скилл — в них правила слоёв, шаблоны кода и грабли:

- `fastapi-onion-backend` — всё в `backend/`;
- `fsd-zustand-frontend` — всё в `frontend/`.

## Команды

Бэкенд (запускать из `backend/`: импорты в коде идут от `src/` — `from api.routers import …`):

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
python src/main.py                 # uvicorn с reload на :8000, Swagger — /docs
```

Отладка — VS Code, конфигурация «Backend: FastAPI» в `.vscode/launch.json` (без `--reload`,
интерпретатор — `backend/.venv`).

Настройки — переменные окружения или `backend/.env` (`src/core/config.py`): `EXCEL_PATH`,
`HEADER_ROWS` (3), `WATCH_INTERVAL_SEC` (1.0), `CORS_ORIGINS` (`http://localhost:5173`).

Фронтенд (из `frontend/`; шаблон Vite `react-ts`: Vite 8, React 19, TypeScript 6):

```bash
npm install
npm run dev          # :5173, /api проксируется на бэкенд (VITE_API_PROXY, по умолчанию :8000)
npm run typecheck    # tsc -b
npm run lint         # oxlint
npm run build
```

UI — shadcn (пресет `b7BFbf6a8`: стиль `base-nova` на `@base-ui/react`, не Radix; иконки
`@tabler/icons-react`; Tailwind v4 через `@tailwindcss/vite`, тема — CSS-переменные в `src/index.css`).
Новый компонент: `npx shadcn@latest add <name>` — по `components.json` ложится в `src/shared/ui`.
`cn` берётся из официального пакета `cn` (замена clsx + tailwind-merge), `shared/lib/utils.ts`
его реэкспортирует. Алиасы `@/` нужны и в корневом `tsconfig.json` — без них CLI shadcn падает.
Предупреждение oxlint `only-export-components` в `shared/ui/button.tsx` — штатное для shadcn.

Алиас `@/` → `src/`. Из `tsconfig.app.json` шаблона убран `erasableSyntaxOnly` — он запрещает
`constructor(private readonly …)`, на котором держится DI в сервисах.

Тестов пока нет ни на бэкенде, ни на фронтенде.

## Поток данных

```
Excel ──► ExcelDatasetRepository (openpyxl, кэш до смены mtime)
            ├─► GET /api/dataset          { version, file_name, columns[], rows[][] }
            └─► GET /api/dataset/events   SSE: event dataset-changed, data { version }
                         │
frontend: shared/api/DatasetSource  ← один запрос и одно EventSource на всё приложение
            ├─► entities/column        ColumnApi(source)
            ├─► entities/column-group  ColumnGroupApi(source)
            └─► entities/dataset       DatasetApi(source)
                  → services → zustand-сторы → pages/ChartsPage (контейнеры) → widgets/features через di.ts
```

Неочевидное:

- **`version` — `mtime` файла в миллисекундах.** Не наносекунды: они не помещаются в `Number` JS.
  SSE не держит наблюдателя за файлом: каждое соединение раз в `WATCH_INTERVAL_SEC` сверяет
  `mtime` и шлёт событие, если он изменился. Данные в событии не передаются — фронт
  перезапрашивает `GET /api/dataset`, только если версия выросла.
- **Первое чтение файла ~6–7 с**, дальше — из кэша. `GET /api/dataset` намеренно синхронная
  ручка (выполняется в пуле потоков), чтобы не блокировать SSE. Ответ ~11 МБ, gzip — ~0,6 МБ.
- **Строки — массивы в порядке `columns`**, не словари.
- **Ключ столбца — текст шапки** (`"Группа / Подстолбец"`), а не буква: на него ссылаются
  конфиги графиков на фронте, вставка столбца в Excel не должна их ломать.
- Недоступный файл (нет, заблокирован, битый) → сервис бросает `DatasetUnavailableError`,
  `main.py` отдаёт 503.

## Особенности Excel-файла

Разбор — `backend/src/repositories/excel_dataset.py`:

- шапка в 3 строки: группа (объединённые ячейки) / подстолбец / номер столбца; пустая
  ячейка группы наследует группу слева, подстолбец `0` считается пустым;
- тип столбца — по содержимому: ≥ 90 % заполненных значений числа → `number`, даты → `date`,
  иначе `string`. Поэтому «Глубина, мм» (~15 % текста) — `string`;
- `"-"`, `" -"`, `"—"` → `null`; строки обрезаются по пробелам. Регистр и хвостовые пробелы в
  категориях («Годен» / «годен» / «Годен ») бэкенд не нормализует;
- столбцы 2021…2026 — флаги `1`/пусто «обследован в этом году»;
- **типы ячеек внутри столбца смешаны**: в текстовой «Марке стали» марки «20», «10», «30» записаны
  числом (31 ячейка), в числовом «Годе выпуска» есть даты-строки. Поэтому вид оси X решает тип
  столбца (`xAxis.categorical`, ставится при броске; для старых конфигов — по большинству ячеек),
  а не отдельные ячейки: на текстовой оси число → строка, на числовой строка → `parseFloat` или
  отбрасывается. Списки значений и фильтры линий тоже считают число в текстовом столбце значением.

## Фронтенд: решения, которые уже приняты

- Состояние — zustand через `createStore(deps)` + провайдер-фабрика; `new` только в
  `app/compositionRoot`. Фичи и виджеты не читают сторы — получают зависимости из своего `di.ts`,
  их раздаёт страница.
- Конфиги графиков хранятся в localStorage (`ChartsLocalRepository` поверх
  `shared/storages/PersistStorage`, ключ `charts`, формат `{ version, charts }`). Бэкенд их не хранит.
  Хранятся только конфиги; точки каждый раз считает `ChartModel.buildPoints`.
- Агрегация — на фронте по всем строкам (решено для тестового; перенос на бэкенд —
  замена репозитория в composition root).
- Роль столбца считает `ColumnModel`: любое число — мера (можно на Y), остальное — измерение. Годы
  («Год выпуска», «Год ввода…») — тоже меры, но с пометкой `isYear`: `ChartModel.getAggregations` даёт им
  только среднее/мин/макс (сумма годов бессмысленна), а линия-год (`Series.isYear`) рисуется без
  разделителя тысяч и со шкалой не от нуля. В регулярках по кириллице не использовать `` — в JS он
  только для латиницы.
- Отдельных столбцов-дат в файле нет: все 4 даты — подстолбцы группы «Дата проведения обследования»,
  поэтому секция «Даты» панели полей пуста и должна скрываться.
- Ось X — ровно одно поле любого типа; ось Y — несколько линий, только меры: числовые столбцы
  (`sum`/`avg`/`min`/`max`) и «Количество» (`columnId: null`), суженное фильтром по значению
  категории. Ключ линии в Recharts — `series.id`.
- Группа столбцов («Марка стали», «Типоразмер тройника» …) на оси открывает окно выбора
  **одного** подстолбца; «+» у группы в панели раскрывает подстолбцы для перетаскивания по одному.
- `Series.xColumnId` — свой столбец оси X для линии (график «Выпуск и ввод»: обе линии по годам,
  одна считает по «Году выпуска», другая — по «Году ввода»). Общая ось X — `chart.xAxis`.
- Пустая группа в `buildPoints`: для `count` — 0 (строк нет — это ноль), для `avg/min/max/sum` — `null`
  (разрыв линии). Точка X заводится по всем строкам с X, до фильтра линии — иначе год, где фильтр
  отсёк всё, выпадает с оси и линия соединяет соседей. Одиночная точка между разрывами рисуется
  маркером (`LineChartView`, у остальных `dot` нет).
- Цвет линии — `colorSlot` 1…8 → `--series-N` в `src/index.css` (эталонная палитра скилла dataviz,
  светлая и тёмная). Слот закрепляется при создании линии и не меняется при удалении соседних.
  Цвета темы `--chart-1..5` пресета `mist` — серые, для линий не годятся.
- Recharts по умолчанию сортирует легенду и подсказку по алфавиту — `itemSorter` задан явно.
- Пресеты (4 графика из ТЗ) — в `ChartModel` (`model/presets.ts`); репозиторий возвращает `null`, если
  сохранённого нет, и пресеты подставляет сервис. До первого изменения в localStorage ничего не пишется.
- Методы-вычисления сторов (`getVisibleGroups`, `getStandaloneByType`, `getCategoryValues`, `canDrop`)
  принимают данные аргументами — иначе ломаются зависимости `useMemo`. `react-hooks/exhaustive-deps`
  в oxlint включён: предупреждения чинить, а не глушить.
- Перетаскивание: один `AxisDndProvider` (DndContext) на панель и все графики, правила — в
  `ChartModel.canDrop/dropField`, соединение сущностей — `pages/ChartsPage/AxisDndContainer`.
  На Y — меры и виртуальное «Количество строк», на X — любое поле (дата → по годам). Группа открывает
  окно выбора одного подстолбца. **Выбора агрегата в интерфейсе нет** (убран по решению пользователя):
  числовая линия всегда «Среднее», «Количество строк» — количество; `getAggregations`/`aggregation`
  в модели остались — ими пользуется `dropField`, и вернуть выбор — это вернуть селект в окна.
  Подпись числовой линии — просто название поля, без приставки «Среднее · »; со старых сохранённых
  конфигов приставку снимает `ChartModel.migrate` при загрузке (переименованные вручную не трогает).
- Форма графика выбирается по оси X автоматически (`isCategoricalPoints`): годы/даты/числа — линия
  (`LineChartView`), текст (завод, вид дефекта) — вертикальные столбцы (`BarChartView`; короткие подписи прямо, длинные или многочисленные — под наклоном с обрезкой): у категорий
  нет порядка, линия между ними врёт. Для текстовой оси `xAxis.values` — выбранные значения
  (нормализованные; `null` — топ `TOP_CATEGORIES`=15 по частоте во всём файле, без учёта фильтров
  линий — так совпадает с «Топ-15» в окне), `xAxis.showOther` — остальные одним столбиком «Прочие»,
  посчитанным тем же агрегатом по их строкам (не среднее средних). Окно выбора — `xValuesFeature`
  (клик по чипу оси X). Столбики по убыванию первой линии, «Прочие» последним и приглушены.
  Выбор «линия / столбики» — один, в `entities/chart/ui/ChartView` (его используют и карточка, и окно
  «на весь экран» `expandChartFeature`; там `size="full"` — шире колонка подписей категорий).
- Сетка графиков 2 колонки; последняя ячейка — плитка «+» того же размера (`addChartFeature`).
